Meeshy · Vue conversation · Volume 4 — la spec, ancrée dans le code

Focal Grandeur Nature

Le principe de ce volume : le design proposé fait foi — aplati, sans bulles, une seule carte (le message au point), défilement extra-fluide. Le relevé du code réel (MeeshyColors.swift, ThemeManager.swift, ColorGeneration.swift, MessageNameDate.tsx) ne sert qu’à deux choses : ne pas créer de choc (palette indigo, avatars, stickers, composer familiers — et la vue actuelle à bulles toujours à un tap via Aa) et hériter de l’accessibilité (Dynamic Type, VoiceOver). Avec les nouveautés demandées : identité Pseudo · heure, stickers de date collants, pilule jour + heure visible seulement pendant le défilement, et de vrais messages longs et courts pour juger le focus.

Décisions de design (et leurs sources)

Plat, sans bulles — le design proposé fait foi. Pastille 22, identité Pseudo · HH:mm (13/12), texte 15 en colonne au retrait 29, médias nus radius 16. La seule « carte » de l’écran est le message au point (fond #F8F7FF/#13111C + ring accent). Aucune bulle : la hiérarchie vient de la perspective, pas du chrome.
Zéro choc : l’habitude est préservée par les ancres, pas par les bulles. Palette indigo réelle, avatars-initiales, stickers de jour capsule (labels « Aujourd’hui/Hier » de MessageDayLabel), format HH:mm du TimeStringCache, composer et header inchangés. Aa bascule vers la densité Script : la même rangée plate, uniforme, sans perspective — aucune bulle dans aucun des deux modes. La vue bulles historique reste dans l’app derrière le flag pendant la transition, mais elle n’est pas un mode : c’est l’ancien rendu, appelé à s’éteindre.
Extra-fluide, par construction. La perspective n’utilise que transform + opacity : composées sur le GPU, zéro relayout, zéro reflow — 60–120 Hz même sur un fil de 100 messages. iOS : transform + alpha des cellules visibles dans scrollViewDidScroll, la collection inversée et les cellules actuelles restent intactes (POC additive, rien n’est cassé).
Accessibilité : la seule partie copiée sur l’app. Toutes les tailles du design passent par MeeshyFont.relative (Dynamic Type) ; VoiceOver lit chaque rangée « Karim, 14 h 32, message » — la perspective est invisible pour lui ; prefers-reduced-motion désactive l’effet (le prototype le fait déjà). Le focus ring #31B6BB vient de la vraie formule d’accent (ColorGeneration.swift) : chaque conversation aura le sien.

5 · Spécification d’implémentation — iOS

Architecture, algorithme, et chaque feature existante

Contrat : le mode Focal est une couche de rendu posée sur l’infrastructure existante — ConversationViewModel, MessageStore (fenêtré, cache-first GRDB), ConversationSocketHandler et la UICollectionView inversée de MessageListViewController ne changent pas. Seule la cellule et un pass de scroll changent. Toute feature listée ci-dessous doit fonctionner à l’identique — le temps réel en premier.

BriqueSpécification précise
État du modeenum ConversationReadingMode: String, Codable { case focal, script } + bubbleLegacy transitoire hors flag. Propriété @Published var readingMode sur ConversationViewModel, hydratée à l’init depuis les préférences par conversation (même stockage que « My display » — ConversationPreferencesTab), défaut .focal sous flag reading_modes. Le choix manuel (Aa / Lentille) écrit la préférence — collant. L’orchestrateur ne s’exécute qu’à l’onAppear, jamais pendant la lecture.
CelluleFocalRow.swift (SwiftUI, cotes §3) montée via UIHostingConfiguration dans les cellules existantes — même BubbleContentBuilder en amont (donc mêmes preferredTranslation(for:), mentions, liens). La cellule reste enveloppée par BubbleSwipeContainer (swipe réponse/transfert inchangé) et le .scaleEffect(y:-1) de la collection inversée. En densité Script : la même FocalRow, sans pass de perspective.
FocalScrollerDans scrollViewDidScroll : pour chaque visibleCell, convertir le centre en coordonnées visuelles (convert(_:to:) + inversion), calculer d = max(0, focusY − midY) avec focusY = bounds.height − 150, puis f = min(1, d/380) ; appliquer layer.transform = CATransform3DMakeScale(1−0.40f, 1−0.40f, 1) (anchorPoint fixé une fois à (0.16, 1.0)) et alpha = 1 − 0.82f. Coût O(cellules visibles), aucune invalidation de layout, aucun blur/ombre → 120 Hz ProMotion. La cellule la plus proche du focus (midY ≤ focusY + 95) reçoit isFocused via une clé custom de UICellConfigurationState ; FocalRow rend alors la carte (fond backgroundSecondary, radius 16, ring 1.5 conversation.accentColor, texte 15→16 animé springFast).
Premier message lisibleRègle : le tout premier message de l’historique doit pouvoir atteindre la bande de focus. Sur la collection inversée, ajouter un inset de tête côté messages anciens : contentInset = bounds.height − focusBand − hauteurPremièreRangée (≈ bounds.height − 190), matérialisé par une vue « Début de la conversation · {date} » (caption, textMuted). Le correctif est visible dans le prototype §2.
Stickers & piluleMessageDaySeparator inchangé pour les capsules inline ; MessageDayStickyOverlay étendu : texte « {jour} · {HH:mm} » du premier message visible (labels MessageDayLabel, heure TimeStringCache), opacité 1 sur scrollViewDidScroll, fondu 0 après 900 ms sans événement (timer réarmé), masqué quand le header étendu est ouvert (comportement existant conservé).
Lentille + AaDans floatingHeaderSection (ConversationView.swift) : pastille du mode courant (nom + point accent) ouvrant la feuille des modes, bouton Aa adjacent (44×30, MeeshyRadius.full). Transitions par fondu d’échelle springDefault (zoom sémantique). VoiceOver : « Mode de lecture, Focal, bouton ».
Perf & accessibilitéBudget : pass de scroll < 1 ms/frame (profiler sur iPhone 12) ; zéro allocation dans le pass ; UIAccessibility.isReduceMotionEnabled → pas de transform (Script visuel, focus par surbrillance seule) ; VoiceOver → la perspective n’existe pas : chaque cellule lit « {Pseudo}, {heure}, {contenu} » + traits existants ; Dynamic Type via MeeshyFont.relative(13/12/15/16) ; emoji-only conserve 90/60/45 pt.

7 · Recette — critères d’acceptation

La définition de « fini »

Focale. Le tout premier message de l’historique atteint la bande de focus et se lit plein cadre (inset de tête). Un message long de 6 lignes net occupe l’attention ; à 400 px au-dessus, il pèse ≤ 20 % d’opacité. Le focus suit le défilement sans à-coup ni oscillation entre deux rangées (hystérésis 95 px).
Fluidité. 60 fps minimum sur iPhone 12 / mid-range Android (web), 120 Hz sur ProMotion ; le pass de scroll n’alloue pas et ne déclenche aucun relayout (Instruments / DevTools Performance à l’appui). Fil de 100+ messages avec carrousel, audio et PDF : aucune chute mesurable vs la liste actuelle.
Temps réel. Chaque ligne de la matrice §5 vérifiée en Focal ET en Script : message entrant (au fond / pas au fond), typing, présence, ✓✓ et lu, réaction live, traduction tardive (swap + 🌐), édition, suppression, optimiste + échec + retry, pagination haut, recherche → focus. Aucune bulle visible dans les deux densités — la seule carte est le focus.
Chrono. Pseudo · HH:mm en tête de groupe uniquement ; stickers de jour collants aux libellés MessageDayLabel ; pilule « jour · heure » visible pendant le défilement, invisible 900 ms après l’arrêt, jamais affichée à l’ouverture.
Accessibilité. VoiceOver/lecteur d’écran : contenu intégral, ordre chronologique, zéro artefact de perspective. Reduced motion : rendu Script + focus par surbrillance. Dynamic Type XL : la rangée s’étire, la focale reste lisible. Contrastes AA sur les deux thèmes.
Réversibilité. Aa bascule Focal ⇄ Script instantanément, préférence collante par conversation, « revenir en mode auto » disponible. Flag off : l’app est bit-à-bit identique à aujourd’hui.

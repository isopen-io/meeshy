## Défaut (maintenabilité / cohérence) : l'indigo de marque, écrit en dur TROIS fois

L'accent affiché **avant** qu'un auteur/profil soit connu — l'indigo de marque Meeshy,
`#6366F1` — était réécrit **en dur** sur trois surfaces web :

| fichier | constante locale |
|---|---|
| `routes/profile-sections.tsx:690` | `export const DECOR_ACCENT = '#6366F1'` |
| `components/decor-preview.tsx:43` | `const FALLBACK_ACCENT = '#6366F1'` |
| `components/pack-sheet.tsx:28` | `const FALLBACK_ACCENT = '#6366F1'` |

Les trois servent le **même rôle** : le repli de `authorAccentColor(id, name)` quand la
donnée de profil n'est pas encore là —

```tsx
const accent = profile.data === undefined ? FALLBACK_ACCENT
             : authorAccentColor(profile.data.id, profile.data.displayName ?? …);
```

**Pourquoi c'est un défaut (et pas juste du cosmétique).** `#6366F1` est l'indigo de
marque, déjà défini **une fois** côté iOS (`ColorGeneration.swift` `indigo500`) et
projeté par le jeton `--ios-indigo-500` (`packages/design-tokens/ios.css`, généré
depuis iOS). C'est aussi la première entrée indigo de `VIBRANT_PALETTE`
(`@meeshy/shared/utils/conversation-colors.ts`), la palette dont `authorAccentColor`
tire TOUS ses accents. Trois littéraux recopiés sont **trois jumelles divergentes en
puissance** : si la marque changeait d'indigo, ces trois replis resteraient en silence
sur l'ancienne teinte pendant que les accents calculés, eux, suivraient la palette.
C'est exactement la jumelle que la loi « UNE source de vérité » interdit.

**Pourquoi l'angle mort a tenu.** Chaque littéral était « correct » pris isolément
(même valeur que le jeton) ; le gate d'harmonie (`check-design-harmony.mjs`) les
comptait comme violations `hex` mais sans dire qu'ils partageaient une sémantique. Le
voir exige de rapprocher les trois sites et de reconnaître le rôle commun — ce que les
pistes 76w/78w avaient noté sans le solder.

## Correction

- **Source UNIQUE** : `export const DEFAULT_AUTHOR_ACCENT = '#6366F1'` ajoutée à
  `@meeshy/shared/utils/conversation-colors.ts`, **à côté de `authorAccentColor`** dont
  elle est le repli, avec doc-comment liant explicitement les quatre expressions de la
  même valeur (iOS `indigo500`, jeton `--ios-indigo-500`, entrée indigo de
  `VIBRANT_PALETTE`, et cette constante).
- **Câblage** : les trois surfaces IMPORTENT la constante au lieu de réécrire le
  littéral. `DECOR_ACCENT` reste exporté (ses consommateurs — `routes/profile.tsx` —
  ne changent pas) mais devient `= DEFAULT_AUTHOR_ACCENT`. Les deux `FALLBACK_ACCENT`
  locaux disparaissent au profit de `DEFAULT_AUTHOR_ACCENT` directement.
- **Pourquoi dans `@meeshy/shared` et non web-local** : `authorAccentColor` et
  `VIBRANT_PALETTE` y vivent déjà ; les deux composants importent **déjà** de ce module
  exact. La source du repli appartient donc là — une vraie source unique monorepo, pas
  un 4e exemplaire côté web. (Ceci reste du travail WEB : on corrige un défaut de la
  consommation web d'un util partagé, sans toucher iOS/Android.)
- **Pourquoi pas `var(--ios-indigo-500)` directement** : ces replis sont typés comme la
  sortie de `authorAccentColor` (une chaîne hex `#RRGGBB`) et transitent vers un calcul
  d'accent / un style inline attendant un hex, pas une `var()` CSS. La constante hex est
  la bonne forme.

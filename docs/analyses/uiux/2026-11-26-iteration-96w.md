## Le défaut retenu (SURGICAL, observable, testable, non couvert)

**Jumelle divergente d'un formateur `m:ss`** — le concept « durée média en
minutes:secondes » a cinq définitions dans `apps/web`, pour trois comportements.
La plus visible produisait un chiffre FAUX à l'écran.

`videoDurationLabel` (`lib/view/media-grid-layout.ts`) — le badge peint sur une
vignette vidéo (`video-tile.tsx:30`, `content-card-visual.tsx:94`) —
calculait `Math.round(durationMs / 1000)` **sans garde**, alors que le
formateur SOCLE `formatMediaTime` (`lib/view/seek-track.ts`) **plancher**
(`Math.floor`) et garde le non-fini/négatif en `0:00`. Ce socle est celui que
lisent déjà le lecteur (`media-transport.ts`), l'aperçu de citation
(`quoted-preview.ts:272`) et la feuille d'accusés (`message-receipts-sheet.tsx`)
via `attachmentDurationLabel`.

Deux conséquences :
1. **+1 s à l'œil** — pour toute durée à fraction ≥ 0,5 s, le badge annonçait une
   seconde de plus que le MÊME fichier partout ailleurs. Ex. `durationMs = 1500`
   → badge « 0:02 », lecteur/citation/accusés « 0:01 ». C'est une incohérence de
   positionnement (dim. 6) : un seul contenu, deux durées.
2. **« NaN:NaN »** — une durée indéfinie peignait ce littéral, là où le socle
   rend « 0:00 ».

**Parité iOS (lue, non modifiée)** : le badge de vignette
`MeeshyVideoThumbnail.swift:53` appelle `MediaFormat.duration($0 / 1000)` dont le
défaut est `rounding: .down` (`MediaFormat+Duration.swift:45`) — iOS
**plancher**. Le web arrondissait : divergence iOS confirmée, dans le sens où le
correctif RAPPROCHE le web d'iOS.

**Couverture préexistante** : aucune — `media-grid-layout.test.ts` n'affirmait
rien sur `videoDurationLabel`. Le témoin est donc une couverture neuve.

## Correction

`videoDurationLabel` DÉLÈGUE désormais au socle :
`export const videoDurationLabel = (durationMs: number): string => formatMediaTime(durationMs / 1000);`
— site unique, plancher + garde hérités, aucune arithmétique recopiée.
